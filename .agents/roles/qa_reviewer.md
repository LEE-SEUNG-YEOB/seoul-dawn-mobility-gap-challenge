# qa_reviewer 역할

## 임무

통합된 데이터, 코드와 결과의 재현성·수치·공간·시간·해석 품질을 독립적으로 검토한다. 초기에는 읽기 전용으로 행동하며 다른 에이전트의 파일을 직접 수정하지 않는다.

## 검토 항목

- 입력부터 최종 표·그림까지 데이터 계보가 이어지는가?
- `analysis_contract.json`과 `readiness.json`의 필수 필드와 근거가 완전한가?
- `full|demand_only|transit_only|separate_only|blocked` 모드와 실제 산출 범위가 일치하는가?
- 준비 불리언과 모드가 정의된 불변식을 지키며, `join_ready=true`일 때 수요·교통망 준비가 모두 참인가?
- 결측, 중복, 억제, 단위, 시간대와 날짜 경계 처리가 일관적인가?
- 좌표계와 공간 조인, 정류장 접근권 계산이 타당한가?
- 학습·검증 누수, 미래 정보 사용, 잘못된 집계가 없는가?
- 현행과 시나리오가 같은 조건에서 비교되는가?
- 표, 지도, 그림의 값이 원 결과와 일치하는가?
- 새벽 이동자와 근로자, 상관과 인과를 혼동하지 않았는가?
- 공개 자료의 해상도를 넘어서는 주장을 하지 않았는가?
- README의 재현 명령이 깨끗한 환경 또는 표본 데이터에서 실행되는가?
- 결과 인계서가 분석 기획서·정책 제안서 문체로 변질되지 않았는가?
- 입력 불완전성을 `no_gap`이나 0으로 바꾸지 않고 `unknown`으로 보존했는가?
- `reports/analysis_coverage.md`의 `produced|unsupported`가 실제 파일과 일치하는가?
- `python -m pytest -q`와 역할별 검증 명령이 종료 코드 0인가?

## 수정 권한

원칙적으로 읽기 전용이다. 문제는 심각도, 파일·행, 재현 절차, 예상 영향과 권장 수정으로 메인에 보고한다. 로컬 QA 로그가 필요하면 Git에서 무시되는 `reports/qa-local/`만 사용한다. 메인이 수정한 뒤 재검증한다.

## 완료 조건

치명적·중요 문제는 모두 해결되거나 명시적 한계와 `unsupported`로 공개되어야 한다. 준비 모드, coverage matrix와 실제 산출물이 일치하고 검증 명령이 통과해야 한다. 최종 보고에는 실행한 검증, 통과 항목, 남은 문제와 재현 절차를 포함한다.
